**Dragabyte UI review — 12 September 2026**

The highest-impact defects are incorrect rename results that can make a retry rename an unselected file, parent/child rename ordering, and a scanner layout that collapses at 800×600. No application code was changed during this review.

**What was tested**

Started the saved `dragabyte-desktop-dev` configuration (`npm run tauri:dev`). It launches the client in `apps/client`, Vite on port 5173, and the Rust desktop app. Playwright 1.63.0 then connected to the actual Windows WebView2, version 152.0.4191.66, using a temporary debugging configuration. This follows Playwright's [WebView2 attachment method](https://playwright.dev/docs/webview2). File-picker return values were supplied automatically; scan, collection, and rename commands used the real Rust backend except for the explicitly identified replay.

All file changes were confined to `%TEMP%\dragabyte-ui-review-20260912\fixtures`. The nested scan fixture contains 8,195 files, 92 folders excluding the root, a branch reaching 19 folder levels below the root, empty folders, and a zero-byte file. Expected and observed totals both equal **5,251,156 bytes**.

**Confirmed defects, ordered by impact**

1. **P1 — A failed rename is marked successful; retrying can rename the wrong file.** Create `alpha.txt` and an existing `new-alpha.txt` with different contents. Add only `alpha.txt`, add prefix `new-`, and execute. Rust returns `successCount: 0` and a destination-exists error, but the row becomes `new-alpha.txt` with a green check. Change the prefix to `fixed-` and execute again: the previously unselected destination becomes `fixed-new-alpha.txt`; the selected `alpha.txt` remains untouched. A mixed two-file batch likewise marked both rows successful when only one succeeded. Return per-item outcomes, preserve failed source paths, and update only successful items from the submitted operation plan. [False success](ui-review-2026-09-12/14-rename-collision-false-success.png), [wrong-file retry](ui-review-2026-09-12/24-rename-retry-changes-wrong-file.png), [filesystem evidence](ui-review-2026-09-12/edge-cases.json). Relevant code: `BulkRenameView.tsx:882–926`, `main.rs:147–186`.

2. **P1 — Renaming a selected parent first breaks its selected child.** Add `Folder` through Folder, then add `Folder/inside.txt` through Add Files. Apply prefix `new-` to both. The directory becomes `new-Folder`; the child operation fails because its old path has disappeared. The actual child stays `new-Folder/inside.txt`, while the UI claims `new-inside.txt` succeeded. Plan dependent operations in a safe order and update descendant paths after ancestor moves. [Screenshot](ui-review-2026-09-12/16-rename-parent-child.png), [native outcomes](ui-review-2026-09-12/renaming.json). Relevant code: `main.rs:151`, `BulkRenameView.tsx:885–922`.

3. **P1 — At 800×600, scan results collapse into unusably short panes.** Scan the nested fixture, then resize to 800×600. Performance and filter controls consume most of the window; the explorer scroll area measures only 16 px high and the detail area 25 px. The outer page does not provide more vertical space. At 640×480 the detail pane reaches zero height. Put optional scan settings behind a disclosure and give results a usable minimum height; allow normal page scrolling when panels stack. [800×600](ui-review-2026-09-12/scan-800x600.png), [measurements](ui-review-2026-09-12/responsive.json). Relevant code: `ScanView.tsx:3653`, `ScanView.tsx:4045`.

4. **P2 — An active search becomes inaccessible below 1024 px.** At 1200 px, enter `nothing-matches-this-query`, then resize to 800×900. The results still say zero matches, but the search field and its clear control disappear. Clear Filters leaves the query unchanged. Keep the search/clear control reachable at every supported width, including when a query is already active. [Screenshot](ui-review-2026-09-12/28-scan-hidden-search.png), [recorded query state](ui-review-2026-09-12/final-checks.json). Relevant code: `ScanView.tsx:3499`.

5. **P2 — Rename validation happens too late or is absent.** Prefix `bad:` is previewed and accepted for execution on Windows; the filesystem rejects it, followed by the false-success state in finding 1. Prefix `..\moved-` actually moves a file into its parent directory. An invalid replacement regex, `[`, is silently ignored, without an invalid field state. Existing destinations are not flagged in preview. Validate basenames, path separators, platform-invalid names, regex syntax, and destination conflicts before execution. Disable Rename when there are no valid changed items; it is currently enabled even with no rules. [Invalid name](ui-review-2026-09-12/15-rename-invalid-name.png), [regex](ui-review-2026-09-12/18-rename-invalid-regex.png), [unexpected move](ui-review-2026-09-12/23-rename-path-separator.png).

6. **P2 — Rename controls and previews become inaccessible in narrow windows.** With files loaded, resize to 640×480: Clear All is clipped by the rule panel. At 390×844, Add Files, Folder, Import, and almost the entire preview are obscured, while Rename remains active. The 800×600 renamer remained usable. Stack the rule panel or move it into a drawer on narrow windows, and keep file selection, preview, and execution reachable. Alternatively, enforce a tested minimum window size. [640×480](ui-review-2026-09-12/rename-640x480.png), [390×844](ui-review-2026-09-12/rename-390x844.png). Relevant code: `BulkRenameView.tsx:1056`.

7. **P2 — Tree percentages describe the wrong quantity.** In the completed fixture, Group-7 occupies about 21% of the scanned total, as the chart shows, but its tree row says `100% occupied`. Group-6 says 88% while the chart shows about 19%. The tree percentage is normalized against the largest entry at the same depth. Remove the occupancy claim or calculate a consistent percentage of the parent; a relative size bar can remain without a misleading percentage label. [Screenshot](ui-review-2026-09-12/04-scan-complete.png). Relevant code: `ScanTree.tsx:26`, `ScanTree.tsx:264`.

8. **P2 — Successful checks survive changes to the preview.** Rename `alpha.txt` to `new-alpha.txt`, then edit the prefix to `again-`. The new, unexecuted preview `again-new-alpha.txt` retains a green success check. Reset result status when the proposed operation changes, and distinguish the executed name from the next preview. [Screenshot](ui-review-2026-09-12/12-rename-stale-success.png). Relevant code: `BulkRenameView.tsx:622`.

9. **P2 — Importing a vanished folder gives no recovery feedback.** Supply an Import selection pointing to a folder that no longer exists. The real collector returns an empty array and the UI stays at Files (0), with no error or indication that the selection failed. This simulates a folder disappearing between picker selection and collection; the picker itself was bypassed. Return a missing-path error and show it at the import control. [Screenshot](ui-review-2026-09-12/20-rename-import-error.png), [response evidence](ui-review-2026-09-12/edge-cases.json). Relevant code: `main.rs:458`, `BulkRenameView.tsx:738`.

10. **P3 — Minor control and empty-state inconsistencies.** In the browser check, open a rule's Both dropdown and press Escape: the menu stays open. Use a native select or implement standard dismissal/focus behavior. After a successful empty scan, the chart asks the user to run a scan despite the completed zero result; omit that chart prompt in this state. [Dropdown observation](ui-review-2026-09-12/browser-initial.json), [empty scan](ui-review-2026-09-12/06-scan-empty.png).

**Additional defect reproduced with controlled timing**

**P2 — Editing rules during execution can falsify the final displayed name.** A real rename changed `alpha.txt` to `first-alpha.txt`; the harness held its response before delivery. While Rename was disabled and its spinner was visible, the prefix field and Clear All remained enabled. Changing the prefix to `second-` and releasing the real response made the UI show `second-alpha.txt` with a success check. The disk still contained `first-alpha.txt`. Keep configuration stable during execution, and reconcile results against an immutable submitted plan. This was verified with a delayed native response, not a naturally slow network share. [Pending state](ui-review-2026-09-12/29-rename-pending.png), [incorrect result](ui-review-2026-09-12/30-rename-edited-during-execution.png), [filesystem evidence](ui-review-2026-09-12/final-checks.json).

**Suggested improvements, not additional confirmed defects**

- Reduce the scanner's permanent settings area. Keep Scan Folder, search, and useful progress visible; reveal priority, throttling, and detailed filters when requested. This also addresses the compact-window failure without adding explanatory copy.
- Clarify Folder versus Import with direct choices such as Add folders and Add folder contents, potentially grouped under one Add control. The current distinction depends on tooltips.
- When imported files share a basename, reveal the parent folder where it helps distinguish them. Consider individual row selection/removal so users can exclude one item without rebuilding the entire selection. [Duplicate-name preview](ui-review-2026-09-12/17-rename-import.png).
- Profile native event bursts before making further performance claims. The fast native run produced early discovery but few intermediate rendered sizes; recorded long tasks ranged from 70–412 ms and a post-scan expansion took 980 ms. The slower replay remained usable. Development mode, instrumentation, and concurrent builds prevent attributing those timings solely to application code. Commit final totals and the completion state together to avoid the observed brief transition with old partial sizes and cleared busy indicators.

**Verification limits and artifacts**

This was a Windows development build, not an installed release. Viewports were emulated inside the real WebView; physical resizing, DPI changes, native pickers/dialogs, OS drag-and-drop, shell integration, network shares, and Linux/macOS behavior were not verified. Access-denied entries were not forced. Template persistence and rule drag reordering were not tested. Scan throughput was not benchmarked against a baseline.

The normal scan stream, exact totals, cancellation, empty/error recovery, and filesystem rename outcomes were native. Sustained progress screenshots use a slowed replay of real events; the in-flight rename test delays a real response. Browser-only startup/layout checks used native-call stubs and are identified by the `browser-` filename prefix. Early setup captures and startup scans of the review settings file are not treated as product findings. The first fast-scan screenshot was captured after completion, so it is not evidence of an intermediate state.

Source hashes for ScanView, BulkRenameView, and renameLogic were unchanged from inspection to completion. The desktop compiled successfully. No lint/build changes or dependency changes were made to the project. The saved desktop configuration was restarted after removing the test session.
